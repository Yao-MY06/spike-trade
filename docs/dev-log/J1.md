## 2. 实现结果

- 下单链：`seckill.lua` 原子判断/扣减/写 zset → 同请求写 `tb_seckill_outbox` → relay 带 confirm/mandatory 发布 → 消费者单事务插订单并条件扣 DB 库存。
- 幂等：订单主键挡住同消息重投；订单 `(user_id,voucher_id)` 唯一索引挡住同用户第二单；outbox 同唯一键挡住重复请求。
- 失败：可重试错误最多 3 次；`NonRetryableSeckillException` 立即重发布到 `seckillDlx`/`seckillDlq`，消息头保留异常信息。
- 对账：A-E 五类都识别；A 回滚孤儿预约，C 重发或终止，B/D/E 只报告。
- 可追踪：接口返回单号 = `tb_seckill_outbox.id` = 消息头 `message_id` = `tb_voucher_order.id`。

## 4. 踩坑与处理

1. **Spring AMQP recoverer 使用独立模板**：`RepublishMessageRecoverer` 不携带 `CorrelationData`，全局 confirm 回调必须判空。
2. **recoverer 的确认顺序风险**：该版本 recoverer 在 broker 确认死信前就可能 ack 原消息；若死信发布失败，可能丢消息。对账 C 类负责从 `status=SENT` 且无订单的数据中补发/终止。
3. **异常包裹**：监听重试需要 `traverseCauses=true`，否则包装异常可能被误判。`NonRetryableSeckillException` 被配置为不重试。
4. **非法 JSON**：fastjson 抛出的异常在 Consumer 内转为 `NonRetryableSeckillException`，直接进入 DLQ。
5. **事务代理**：Handler 必须是独立 Spring Bean，`@Transactional` 才能在 Consumer 调用时生效。
6. **先插订单再扣库存**：库存条件更新失败时抛异常，让整个事务回滚订单；重复主键且同 id 已存在则正常确认。
7. **队列声明兼容**：`seckillQueue` 保持无参数声明，只新增 `seckillDlx`/`seckillDlq`。实测队列 arguments 为 `[]`，无 `PRECONDITION_FAILED`。
8. **测试配置覆盖**：测试 resources 直接放 `application.yaml` 会遮蔽主配置；已改为 `application-test.yaml` + `@ActiveProfiles("test")`，只覆盖 relay/对账/listener。
9. **日志噪声**：既有 ID 并发测试打印 30,000 行，已改为断言 30,000 个 ID 唯一，避免证据不可读。
10. **Git Bash 路径转换**：`rabbitmqadmin` 的 `--vhost=/` 会被转换成 Windows 路径；`lib.sh` 对 `mq_admin` 使用 `MSYS2_ARG_CONV_EXCL='*'`。
11. **日志脱敏**：通用名称 `redis` 不能全字符串替换，否则 JSON 字段 `redisStock` 会被破坏；只在 docker 命令上下文中替换。
12. **既有 `@author` 字面值与 MQ 用户名相同**：不属于本模块改动范围；lint 只扫描 MQ 用户名且排除 `@author` 行，未修改这些注释。
